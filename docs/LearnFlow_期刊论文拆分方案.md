## 0.2 三句话战略判断

1. **最锋利的 novelty 不是"我们的引擎更好"，而是"没人检验过 85% 规则在真实学习者上是否成立"。** Wilson et al. (Nature Communications 2019) 原文只在人工神经网络与计算神经科学模型上验证，作者本人在多家媒体采访中明确划界："won't apply directly to students"、"More research is going to be needed… outside of computer algorithms"。这是一个**被原文作者亲手点名、有公开数据可答、且无论结果正负都构成贡献**的三重黄金组合。见 P2。
2. **LearnFlow 最大的"缺陷"（60 个引擎、17 个无仲裁 nudge、FOMO 引擎与防沉迷语义直接对立）是唯一一个"只有这个项目能写"的论文。** 别的自适应学习系统机制太少，根本暴露不出"多干预引擎共存冲突"这个问题。缺陷即资产。见 P4。
3. **"0 真实用户数据"不是死刑，但要求彻底重写论文的方法学身份。** 五篇中的三篇（P1/P2/P5）可以**完全**用公开数据集 + 离策略评估（off-policy evaluation）完成，不需要一个自己的用户。P3 需要模拟器但可自证。只有 P4 需要小规模真人（n≈60–120，仅测近端感知指标）。见 §5.3。

## 2.1 【P1】难度量纲的可公度性

### (a) 论文卡片

**暂定标题**
- 中文：《自适应学习系统中难度量纲的可公度性：统一知识追踪、间隔重复与竞技评分的测量框架》
- 英文：*On the Commensurability of Difficulty Scales in Adaptive Learning: A Unified Measurement Framework Bridging Knowledge Tracing, Spaced Repetition, and Competitive Rating*

**一句话研究问题**
当一个自适应系统同时持有 BKT 掌握度、FSRS 记忆难度、Elo 能力估计、DDA 窗口成功率这四个"难度/能力"量时，它们是否可以被置于同一个可校准、可逆、且在仿射变换下稳定的量纲之上？

**核心贡献（3 条，具体）**

- **C1 — 不公度性的形式化刻画与不稳定性定理。**
  证明 LearnFlow 当前 `orchestrator.py:42-44, 511-516` 的线性加权融合 `0.45·BKT + 0.35·DDA + 0.20·optimal` 在数学上**不是良定义的**：BKT 侧 `mastery×9+1` 是有界潜变量的整数化（顺序量级）、DDA 侧是**成功率**（比率量级，且是结果不是难度）、optimal 侧是 Elo→FSRS 的浮点（近似区间量级）。三者的量纲类型不同，线性组合的结果随任一侧的**单调仿射重参数化而漂移**。
  → **可验证命题**：把 BKT 侧从 `mastery×9+1` 改为 `mastery`（即除以 9 再减 1/9），最优权重从 0.45/0.35/0.20 变为一个显著不同的有效权重；而统一量纲方法的输出**不变**。这个 Δ 是可以精确测量的。

- **C2 — 统一难度量纲 UDS（Unified Difficulty Scale）及其可逆映射。**
  以 **"在给定学生能力 θ 下正确作答该题的对数几率"** 为公共货币，构造可逆映射：
  - `Elo θ` → 直接是对数几率尺度（Elo 定义即 400·log₁₀ 赔率），天然是区间尺度 ✅
  - `BKT mastery m` → `logit(m)`，但需处理 m→0/1 的边界（用 Jeffreys 先验平滑）
  - `FSRS Difficulty D ∈ [1,10]` → 经 FSRS 的 retrievability 公式 `R(t) = (1 + F·t/S)^(-C)` 反解出"该题对该生的有效成功率"，再取 logit
  - `DDA 窗口成功率 r` → **不是难度，是难度与能力的联合结果**；须用 `difficulty = θ − logit(r)` 分离（这正是 C1 指出的范畴错误）
  → 统一后给出**标定算法**：在共享题目集上用 Platt scaling / 层级 IRT 联合估计各源到 UDS 的映射参数与各自的置信权重（权重由源的校准误差反推，而非硬编码）。

- **C3 — 目标命中率的实证对比。**
  在公开数据上对比三种方案的"85% 目标命中率"（即被选中的题目实测成功率落在 [0.80, 0.90] 区间的比例）：
  (i) LearnFlow 现有线性融合 + 精确等值匹配；
  (ii) 统一量纲 + 等值匹配；
  (iii) 统一量纲 + 区间匹配 + 置信度加权。
  并报告**仿射变换稳定性**（在 5 种单调重参数化下输出排序的 Kendall τ 漂移）。

**技术资产依据**
- `app/services/optimal_difficulty.py`（564 行）：L1 85% 规则 / L2 FSRS（`:165`）/ L3 Elo-Glicko（`:229`）/ L4 FlowChannel（`:289`）
- `app/services/orchestrator.py:42-44, 511-516`（三源线性加权）、`:109`（`theta = 800 + mastery×1400`）
- `app/services/knowledge_tracing.py`（217 行，BKT `mastery×9+1`）
- `app/services/dda.py`（170 行，窗口成功率 → 1-10）
- 已知缺陷：权重硬编码无标定；564 行模型 4/5 输出被丢弃（`:119` 只取标量）；前端 `challenge_band` low:75/high:85 硬编码（`:195-199`）

**方法路线**
1. **测量论论证**（纯理论，无数据）：用 Stevens 量表分类 + 表示论（representational theory of measurement）刻画四个源的量纲类型，给出良定义性判据。
2. **标定实验**（公开数据）：在共享题目集上拟合各源 → UDS 的映射，用留出交互做校准误差评估（reliability diagram、Brier score、ECE）。
3. **不稳定性实验**（公开数据 + 合成重参数化）：量化线性融合的权重漂移。
4. **端到端对比**（公开数据 + 离策略回放）：对比三种选题方案的 85% 命中率与排序稳定性。

**实验设计概要**
- **数据集**：ASSISTments 2017（≈170 万交互）、EdNet-KT1（可抽样 500 万）、Junyi Academy（≈2500 万）；FSRS 侧用 open-spaced-repetition 开源的 Anki 复习日志（9,999 集合 / 约 3.5 亿条记录；**需二次确认可获取性与许可**）
- **基线**：(a) LearnFlow 现线性融合 0.45/0.35/0.20；(b) 纯 IRT 难度 β；(c) 纯 Elo；(d) 统一量纲但等权
- **评价指标**：ECE / Brier（校准质量）；85% 命中率（目标达成）；Kendall τ 漂移（仿射稳定性）；下游掌握速度 #attempts-to-mastery
- **预期效应量**：校准误差 ECE 从 ≈0.08–0.12 降到 ≈0.03–0.05（中等效应，Cohen's *d* ≈ 0.5–0.8）；85% 命中率从 ≈40–55% 提升到 ≈65–75%（**注意：精确等值匹配使基线极低，这个提升幅度部分是"修 bug"而非"方法好"，论文中必须诚实拆解**）

**目标 venue（三梯度）**

## 2.2 【P2】85% 规则的外部效度检验 ⭐ 第一优先

### (a) 论文卡片

**暂定标题**
- 中文：《85% 规则在真实学习者身上成立吗？——基于百万级学习交互日志的最优错误率离策略评估》
- 英文：*Does the 85% Rule Travel? Off-Policy Estimation of the Optimal Error Rate from Large-Scale Real Learner Logs*

**一句话研究问题**
Wilson et al. (2019) 推导的 15.87% 最优错误率，在真实 K12 / 在线学习者的**非二分类、有提示、有跳过、有遗忘**的学习场景中是否成立？若不成立，最优错误率取值多少，且被哪些变量调节？

**为什么这是最锋利的一篇**

1. **原文作者亲手划界，不是我们硬找 gap**（F2）。Wilson 在 Cosmos 的采访中明确说 85% 规则 "probably won't apply directly to students because they aren't learning binary classification tasks"；在 Futurity / ZME 中说 "The hope is we can expand this work and start to talk about more complicated forms of learning"。
2. **原文的验证域极窄**（F1）：ANN 随机点阵二分类、Law & Gold 生物可信神经网络、MNIST 奇偶/高低二分类。**全部是二分类、无提示、无跳过、无遗忘衰减、无多知识点迁移。**
3. **结果无论正负都是贡献**：
   - 若**成立** → 首次在真实人类学习者上验证一个高引理论，且给出了跨知识点、跨学科的外部效度证据。
   - 若**不成立**（我认为概率更高）→ 对一个被广泛引用、已进入教学设计话语的理论给出大规模证伪与边界条件，这是**更有价值的阴性结果**。
4. **不需要自己的用户**（见方法路线）。

**核心贡献（3 条，具体）**

- **C1 — 识别策略：区分"观测错误率"与"事前预测错误率"，切断内生性。**
  这是本篇**最关键的方法学贡献**，也是绝大多数人做这个研究会犯的错。
  如果直接用学生在这道题上的**观测正确率**作为"错误率"，会引入严重内生性：观测正确率同时被学生能力、题目难度、运气、提示使用决定，且低能力学生天然观测错误率高——于是你会"发现"低错误率效果好，这只是能力混淆。
  → **解法**：用 IRT（1PL/2PL）在全样本上估计学生能力 θᵢ 与题目难度 βⱼ（用**留出的、该次交互之外**的数据拟合，或采用 item-split 策略避免标签泄漏），计算**作答前可知**的预测正确率
  `p̂ᵢⱼ = σ(θᵢ − βⱼ)`，则**事前错误率** `eᵢⱼ = 1 − p̂ᵢⱼ`。
  这个量在给定 (θᵢ, βⱼ) 下与本次作答结果的随机扰动独立，从而可用于因果性的剂量-反应估计。

- **C2 — 用双重稳健离策略评估（Doubly-Robust Off-Policy Evaluation）估计"错误率 → 学习增益"的剂量-反应曲线。**
  - **Treatment（剂量）**：事前错误率 eᵢⱼ，分桶（如 [0,0.05), [0.05,0.10), …, [0.45,0.50)）
  - **Outcome**：学习增益。三个互补定义：(i) 同一知识点的**下一次**作答正确率提升 Δ；(ii) #attempts-to-mastery 的倒数；(iii) 延迟后测（若数据集支持）
  - **估计器**：DR / Augmented-IPW。倾向得分 = 给定学生历史下被分配到该错误率桶的概率（用系统的选题策略估计；对公开数据集，选题策略是"未知的但可从数据反推的行为策略"）。结果模型用 IRT/DKT 预测。
  - **识别假设**：无未测量混杂（条件于 θᵢ、历史正确率、知识点、时间、题目曝光次数、提示使用）。**必须显式讨论该假设的脆弱性并做敏感性分析**（E-value / Rosenbaum bounds）。
  - **输出**：一条剂量-反应曲线 + 峰值点 + Bootstrap 置信区间。**峰值点是否 ≈ 0.1587 就是研究问题的答案。**

- **C3 — 调节变量与失效边界。**
  分层估计剂量-反应曲线，检验：
  (i) **提示使用**（hints_used > 0 vs = 0）——提示会人为压低错误率却不产生学习，这是教育场景相对二分类感知任务的**结构性差异**
  (ii) **知识类型**：程序性（计算/编程）vs 陈述性（记忆）——Wilson 本人说可能只适用于**感知学习**，这个分层直接检验他的猜想
  (iii) **能力分位**：θ 的低/中/高
  (iv) **间隔时间 / 遗忘**：距上次练习该题的时间（把 FSRS retrievability R(t) 作为协变量）——这是 ANN 完全没有的维度
  (v) **跳过/超时**（若数据集有标记）
  → 输出一张"85% 规则适用/失效边界"的可操作判据表。

**技术资产依据**
- `app/services/optimal_difficulty.py` L1 层 85% 规则实现（含 Gaussian/Laplacian/Cauchy 三噪声分布的精确目标值 0.8413 / 0.8161 / 0.7500）
- `app/services/dda.py` 的 `target ∈ [0.75, 0.85]` 窗口启发式（这是一个**现成的对照假设**：工业界凭直觉定的窗口是 75–85%，而不是 84.13%，两者差距可检验）
- 项目缺陷的反向利用：`WHERE difficulty == fused RANDOM() LIMIT 1` 精确等值匹配导致候选集极小 → 这本身说明**现有系统产生的数据无法回答这个问题**，必须用公开数据
- **`app/data/attempts` 表结构缺陷**（无会话 ID、无展示/作答时间戳分离、无跳过标记）→ **必须反馈给 data-engineer 立即改造**，否则未来任何自有部署数据都无法做此分析

**方法路线（数据从哪来、怎么分析）**

```
Step 1  数据获取（全部公开，零自有用户）
        ASSISTments 2017 / EdNet-KT1 / Junyi Academy

Step 2  IRT 拟合（item-split 防泄漏）
        一半交互拟合 (θᵢ, βⱼ)，另一半用于估计；交叉拟合避免过拟合偏差

Step 3  构造事前错误率 eᵢⱼ = 1 − σ(θᵢ − βⱼ)  ← 关键步骤

Step 4  行为策略估计 π̂(bucket | history)（用于 IPW 权重）

Step 5  DR / AIPW 估计每个错误率桶的期望学习增益

Step 6  剂量-反应曲线拟合（样条 or 参数化），峰值点 + Bootstrap CI

Step 7  分层：提示 × 知识类型 × 能力分位 × 间隔时间

Step 8  敏感性分析（E-value）+ 阴性对照（以"未来随机题的正确率"作阴性结局）
```

**实验设计概要**
- **数据集**：3 个公开数据集做**跨数据集复现**（这是本篇能否上 CCF-B 以上的关键）。ASSISTments 2017（数学、有 hint 标记、≈170 万交互）；EdNet-KT1（英语、≈9500 万，抽样 500–2000 万）；Junyi Academy（数学、≈2500 万、有时间戳）
- **基线（对照假设）**：
  (i) Wilson 的 ER* = 0.1587（目标成功率 84.13%）
  (ii) DDA 窗口 [0.75, 0.85] 中点 0.80
  (iii) 恒定难度（不自适应）
  (iv) 随机选题
  (v) 更简单的启发式：正确则加难、错误则减易（固定步长）
- **评价指标**：
  - 主：峰值错误率 ê* 及其 95% CI（是否与 0.1587 显著不同）
  - 次：在 ê* 处的期望学习增益 vs 在 0.1587 处的期望学习增益之差（离策略估计值 + CI）
  - 辅：各分层的峰值漂移（调节效应）
- **预期效应量**：**诚实预告——大概率是小效应甚至零/负效应**。学习增益的剂量-反应曲线很可能是**平坦的**或峰值显著偏离 0.1587（我推测真实峰值更可能在 0.20–0.35 区间，因为教育任务有提示、有多步推理、有部分 Credit）。**但这正是价值所在**：N 百万级使得即使 d = 0.05 也能检出，而"峰值不在 15.87%"是一个对高引理论的干净修正。

## 2.3 【P3】有序动作 Bandit 与心流通道的形式化

### (a) 论文卡片

**暂定标题**
- 中文：《有序动作空间上的难度选择：带遗忘状态的心流通道 Bandit 形式化》
- 英文：*Ordinal-Action Bandits for Difficulty Selection: Formalizing the Flow Channel with Memory-State Dynamics*

**一句话研究问题**
如果把难度选择形式化为**动作空间有序、奖励是学习增益（而非正确率）、状态含记忆衰减**的序贯决策问题，能否得到比"贪心 + 精确等值匹配"更强的理论保证与实证表现？

**核心贡献（3 条，具体）**

- **C1 — 有序动作空间的形式化与遗憾界。**
  现有 LearnFlow 把难度当作**独立动作**（`WHERE difficulty == fused` 精确匹配），等价假设不同难度档的期望奖励互不相关。
  → 事实上难度是**有序**的：相邻难度档的期望学习增益满足 Lipschitz 连续性（|μ(d) − μ(d+δ)| ≤ L·δ）。
  → 因此可用 **continuum-armed / Lipschitz bandit**（Zooming algorithm、HOO）替代独立动作 UCB/TS。
  → **理论贡献**：把标准 regret 界从独立动作的 `Õ(√(K·T))` 改进到有序动作的 `Õ(T^{(d̄+1)/(d̄+2)})`（一维动作下 ≈ `Õ(T^{2/3})`），并给出 Lipschitz 常数 L 的**从数据估计方法**。
  → **这直接回答了"为什么精确等值匹配是错的"**：它丢弃了相邻难度档之间的信息借用，在样本稀缺的冷启动期代价最大。
  **诚实标注**：这是**已有理论的适配（adaptation）**，不是新证明。价值在于证明了"难度选择问题满足该理论的前提假设"，并给出 L 的可估计算法。

- **C2 — 心流通道的二维可标定形式化。**
  现状：`optimal_difficulty.py:289` 的 FlowChannel 输出 BOREDOM/FLOW/STRETCH/ANXIETY 四区，但前端 `challenge_band` 的 low:75/high:85 是硬编码（`:195-199`），且 564 行模型的 4/5 输出被丢弃（`:119` 只取一个标量）。
  → 贡献：把心流通道从"一维正确率区间"升级为**二维区域**：
  - 维度 1：**事前错误率** eᵢⱼ（能力-难度匹配）
  - 维度 2：**努力/时间代价**（反应时 z-score、提示使用次数、放弃率）
  → 给出**边界标定算法**：用 P2 的剂量-反应曲线定 e 方向的边界（**直接消费 P2 的结果**），用反应时分布的分位数定时间方向的边界。
  → 输出：一个**可证伪的命题**——心流区应定义为"学习增益 > 阈值 且 努力代价 < 阈值"的帕累托前沿，而非固定的 [0.75, 0.85]。

- **C3 — 遗忘作为状态转移：把 FSRS retrievability 接进 bandit。**
  现状：难度适配**完全不含时间维度**（无遗忘衰减）。
  → 贡献：定义状态 `s = (θ, {R_k(t)}_k)`，其中 `R_k(t)` 是知识点 k 在时刻 t 的 FSRS 可提取性。同一道题在不同的 `R_k(t)` 下对同一学生有**不同的有效难度**。
  → 于是 MDP 的动作价值函数变为 `Q(s, d)`，选题策略 `π(s)`。这是把"记忆科学"真正接进决策的关键一步，也是 **P1 统一量纲的下游消费者**（动作空间 d 的度量由 P1 定义）。
  → 给出在 retrievability 单调衰减下的**结构性性质**（如最优动作随时间的单调漂移）与可检验预测。

**技术资产依据**
- `optimal_difficulty.py:289` FlowChannel；`:119` 输出被截断；前端 `:195-199` 硬编码 band
- `optimal_difficulty.py:229` Elo/Glicko；`:165` FSRS 难度映射
- 已知缺陷：纯贪心无探索-利用；无遗忘时间衰减；无异质性处理效应；精确等值匹配
- **依赖**：P1（统一量纲 = 动作空间的度量）**+ P2（剂量-反应曲线 = 奖励模型）**

**方法路线**
1. **理论**：证明难度选择满足 Lipschitz 条件；推导有序动作 regret 界；给出 L 的估计器。
2. **模拟器构建**：用 **P2 校准出的剂量-反应曲线 + IRT 参数 + FSRS 记忆模型**构建学习者模拟器。**这是本篇能否成立的关键。**
3. **模拟器验证（不可省略）**：用留出数据检验模拟器的预测误差（对比真实日志上的下一题正确率分布、掌握速度分布）。**若模拟器误差过大，审稿人会一票否决，必须诚实报告。**
4. **离策略评估**：在真实日志上用 IPS / DR 评估所学策略 vs 基线策略的累积学习增益。
5. **（可选，若有部署）**小规模 A/B。

**实验设计概要**
- **数据集**：同 P2（ASSISTments / EdNet / Junyi）+ P2 产出的模拟器
- **基线**：
  (i) LearnFlow 现贪心精确等值匹配
  (ii) DDA 窗口 [0.75, 0.85] 固定步长
  (iii) ε-greedy，独立动作
  (iv) UCB / Thompson Sampling，独立动作（10 档）
  (v) **本文方法**：Lipschitz / Zooming bandit，有序动作 + 记忆状态
- **评价指标**：累积学习增益（离策略估计 + 模拟器内）；regret；心流区内停留比例；#attempts-to-mastery；冷启动期（前 20 次交互）的表现差异（这是有序动作应最能拉开差距的地方）
- **预期效应量**：**小到中等（d ≈ 0.15–0.35）**，且在冷启动期更大。**诚实警告：现有系统"差不多能用"，不要期待数量级提升。** 论文卖点应是**理论保证 + 冷启动改善**，不是全面碾压。

**目标 venue（三梯度）**

| 梯度 | Venue | 分区 | 难度 / 周期 |
|---|---|---|---|
| 冲刺 | **IEEE TKDE** / **ACM TOIS** | **CCF-A** | 极难。TOIS 要求算法创新 + 大规模 IR/推荐实验；TKDE 要求理论 + 实证双全。若只有"适配"没有新证明，会被以"incremental"拒。周期 12–24 个月 |

**风险等级：🟠 中偏高**
- **主要风险 1（无真实 A/B，评估可信度受质疑）**：**缓解**：模拟器 + 离策略 + 模拟器验证三件套；并**明确声明**本文不提供真实部署证据。

## 2.4 【P4】游戏化干预的形式化与冲突仲裁 ⭐ 第二优先

### (a) 论文卡片

**暂定标题**
- 中文：《从 60 个临时引擎到可仲裁的干预单元：游戏化干预的形式化注册表、冲突检测与预算分配》
- 英文：*From 60 Ad-Hoc Engines to Arbitrable Intervention Units: A Formal Registry, Conflict Detection, and Budget Allocation Model for Gamified Learning Systems*

**一句话研究问题**
当一个学习系统里同时存在 60 个行为干预引擎、其中若干**语义直接对立**（催促加时 vs 未成年人时长限制 vs 劝退休息），如何形式化地建模干预空间、**自动检测冲突**，并在**有限干预预算**下分配？

**为什么这是第二锋利的一篇**

1. **这是六篇中唯一一篇"只有 LearnFlow 能写"的论文。** 其他系统的游戏化机制太少（通常 3–8 个），根本暴露不出"多干预引擎共存冲突"这个问题。LearnFlow 的 60 个引擎 / 17 个无仲裁 nudge 生成点 / FOMO 引擎与防沉迷模块语义对立 —— 这些在教科书里是"缺陷"，在论文里是**独一无二的观察场**。
2. **它把"数字丑闻"转化成"方法验证"。** PRD 声称 76 个机制，实测 60 个（去重 ≈53）。**我们不藏，我们把它变成论文里的方法验证案例**："我们首先用提出的 registry 方法审计了本研究依托的系统自身，发现文档声称 76、实测 60、去重后 53，其中 48 个零调用、10 个孤儿模块——这个审计过程本身就是本方法的第一次应用。" 这是**把最危险的弱点变成最强的可信度担保**。
3. **它绕开了自适应游戏化领域最大的坑**（F7/F8）：不做机制消融（样本量不可能），也不声称任何机制对学习有效。

**核心贡献（4 条，具体）**

- **C1 — 干预的元组形式化（Intervention Schema）。**
  定义：`Intervention = ⟨trigger, target_construct, direction, channel, cost, side_effect, precedence⟩`
  - `trigger`：触发条件（事件/时间/状态阈值）
  - `target_construct`：作用构念（参与度 / 坚持性 / 自我效能 / 社交联结 / 时长）
  - `direction`：`↑` 促进 / `↓` 抑制（**这是冲突检测的关键字段**）
  - `channel`：呈现通道（弹窗 / 徽章 / 排行榜 / 推送 / 页面元素）
  - `cost`：干预预算消耗（注意力成本 / 频次占用）
  - `side_effect`：已知副作用集合
  - `precedence`：合规优先级（如未成年保护 = 最高）
  → 把 LearnFlow 的 60 个引擎 / ≈53 个去重机制全部映射到该 schema，报告**映射覆盖率**（预期会有 10–20% 的机制因语义模糊无法归类，**这个"不可归类的部分"本身是一个发现**）。
  → **与既有文献的关系**：Hexad 用户类型（Tondello et al.）与自适应游戏化综述只做"用户类型 → 元素偏好"的**静态匹配**，没有"干预作为可调度、可冲突、有预算的资源"的形式化。这是本贡献的定位。

- **C2 — 三类冲突的自动检测。**
  - **类型 I · 语义对消**：`target_construct` 相同但 `direction` 相反，且触发窗口重叠。
    **真实例**：`FOMOEngine.generate_fomo_nudge`（target=时长, direction=↑）vs `anti_addiction_compliance`（target=时长, direction=↓, 合规强制）vs `feedback_service.generate_rest_reminder`（target=时长, direction=↓）。
    **这是教科书级的可发表观察**——一个系统里同时跑着互相抵消的行为干预。
  - **类型 II · 通道竞争**：同一 `channel` 在同一时间窗内被多个干预争用（17 个无仲裁生成点 → 理论冲突组合数可精确计算）。
  - **类型 III · 目标冲突**：短期参与度 vs 长期学习 vs 合规约束的多目标冲突（形式化为 Pareto 冲突检测）。
  → 给出检测算法（复杂度分析），并在 LearnFlow 上报告检出结果（已确知类型 I 至少 1 组、17 个无仲裁生成点）。

- **C3 — 干预预算与约束分配。**
  每个会话/每日的干预次数上限（防骚扰 + 防习惯化 habituation）。
  → 形式化为**带预算约束的序贯分配问题**：可归约为 budgeted multi-armed bandit / 多选择背包。
  → 给出近似算法 + **regret 分析**（这是本篇能上 CCF-B 以上的理论筹码）。
  → 给出合规硬约束（未成年时长限制）的**优先级抢占语义**证明：在高优先级约束激活时，低优先级干预必须静默——这是一个**可验证的系统性质**，可以写成定理并做 model checking。

- **C4 — 可审计的干预账本（Intervention Ledger）。**
  把项目现状的三个工程问题统一抽象为一个研究问题：**干预状态不可审计**。
  - 11 个内存态容器（进程重启即丢，含 16 技能树全量、XP/等级/连胜、A/B 实验分组）
  - `orchestrator.py:409` 每次 `XPState()` 重建、从不落库 → 每次请求后归零
  - A/B 框架：干预粒度是标量参数、无 `mechanism_id`；81 个 `*Engine` 类**无一读取实验分组**；实验数据在内存
  → 贡献：设计 append-only 的干预账本 schema（含 `mechanism_id`、`intervention_instance_id`、`budget_consumed`、`arbitration_decision`、`preempted_by`），并给出**一致性检查算法**（可检出"预算超支"、"被抢占却仍执行"、"决策无记录"三类违规）。
  → **这个账本同时是 P6（区块链）的替代方案**：用 Merkle tree + 周期性公开锚定就能拿到防篡改与可审计性，**不需要任何区块链**。

**技术资产依据**
- 60 个游戏化机制（实测）/ ≈53 去重 / 81 个 `*Engine` 类；逐文件：positive(7/7)、deep(10/7)、ux(12/8)、social(8/4)、duolingo(8/8)、team(7/6)、v3(5/5)、gamification(12+/10)、habit(PRD 遗漏/5)

## 2.5 【P5】LLM 难度标注的可靠性边界

### (a) 论文卡片

**暂定标题**
- 中文：《机器共识不是人类难度：面向自适应学习的大语言模型题目难度标注审计》
- 英文：*Machine Consensus Is Not Human Difficulty: Auditing LLM-Based Item Difficulty Annotation Against Adaptive-Learning Ground Truth*

**一句话研究问题**
当 LLM 被用作"离线难度标注 → 在线自适应决策"的先验时，LLM 标注的难度与**真实学习者感知的难度**一致性有多高？在什么条件下这个先验会**损害**（而非改善）自适应系统的决策？

**为什么这篇有存在价值（而不是又一个 "LLM + X"）**

LearnFlow v2 规划中明确写了 "LLM 离线标注 + 在线决策"。而按 F5，**这个前提在学界尚无共识，且存在直接矛盾的两派**：
- 乐观派：LLMcompare 报与人类标注 Pearson r ≈ 0.80–0.82
- 悲观派：20+ 模型 × 4 领域的大规模研究报 Spearman ρ < 0.5，且发现**模型越大越不对齐**、模型收敛于"机器共识"而非人类难度、元认知近乎随机

**因此，本篇的定位是"审计与边界条件"，不是"我们用 LLM 做了标注"。** 这个定位决定了它是否是真论文。

**核心贡献（4 条，具体）**

- **C1 — 以真实学习者响应校准的 IRT 难度为 ground truth 的大规模对齐审计。**
  设计：`N` 个模型（覆盖开源/闭源、大/小、通用/数学专用）× `K` 个学科（K12 数学 / 语文阅读 / 编程 / 科学）× `M` 道题。
  - **Ground truth**：**不是**人类专家打分，**而是**用真实学习者响应数据经 IRT 标定出的难度 βⱼ（这是"学习者实际感知的难度"，正是自适应系统需要的量）。
  - **测量**：Pearson r、Spearman ρ、二次加权 Kappa（QWK，按难度分位分箱）、以及**校准误差**（LLM 的系统性偏移方向）。
  - **误差分解**：按学科 × 题型（选择/填空/编程/证明）× 难度分位（低/中/高）× 模型规模 × 提示策略（零样本/思维链/给出学生画像/成对比较）。
  → 输出一张"在哪些格子里 LLM 标注可用、在哪些里不可用"的**边界地图**。

- **C2 — "机器共识陷阱"的量化与证伪。**
  悲观派观察到模型收敛于机器共识，但**没有给出可操作的判据**。
  → 贡献：精确测量 **inter-model agreement**（模型间一致性）与 **model-human agreement**（模型-人类一致性），并证明前者显著高于后者。
  → **关键的可操作结论**：这意味着**"用多模型投票/集成来提高难度标注置信度"这一常见做法在难度标注任务上是错误的**——集成会提高模型的相互一致性，却不提高与人类的一致性，反而**放大**系统性偏差。
  → 给出判据：`ρ(inter-model) − ρ(model-human) > δ` 时，集成策略应当被禁用。**这是一个直接可执行的工程判据，且是对乐观派（LLMcompare 用成对比较 + Bradley-Terry 本质上也是一种聚合）的正面学术对话。**

- **C3 — 决策层面的影响评估：先验偏差 → 学习增益损失。**
  这是本篇**从"又一个相关性研究"升级为"CS 论文"的关键一步**。
  → 把 LLM 先验接入 **P3 的 bandit 框架**，做离策略/模拟器评估，量化：
  `先验偏差 δ ⇒ 累积学习增益损失 Δ(δ)`
  → 输出一条**敏感度曲线**，并给出**"何时该用 / 不该用 LLM 先验"的可操作阈值**（例如：当标注-真实相关性 ρ < ρ* 或先验偏差 |δ| > δ* 时，使用 LLM 先验的期望累积收益低于不使用）。
  → **这个贡献直接决定了 LearnFlow v2 的架构是否成立**，有实际工程价值。

- **C4 — 层级贝叶斯校准：用少量在线响应压过有偏先验。**
  提出 `LLM prior → IRT posterior` 的层级校准模型，并**回答一个工程上真正关心的问题**：
  "**需要多少条真实在线作答，才能把有偏的 LLM 先验纠正到可用的精度？**"
  → 通过模拟 + 公开数据验证给出 N* 的估计与置信区间。
  → 这与 Liu/Bhandari/Pardos (2024) 的"混合 50 真人 + LLM 集成"发现直接对话（他们报 ρ 从 0.89 → 0.93），但我们的贡献是**给出 N* 的定量边界与失效条件**，而不只是一个数字。

**技术资产依据**
- v2 规划中的 "LLM 离线标注 + 在线决策"（**本项目当前 0 个 LLM 调用**）
- `optimal_difficulty.py` 的四层结构（LLM 先验将作为第五层或一个替换层）

- 外部依据：F5（学界分裂的两派结论）

**方法路线**

## 2.6 【P6】区块链教育大数据可信处理 🔴 建议放弃

### (a) 论文卡片（条件性）

**暂定标题（若必须做，只能做这个版本）**
- 中文：《教育学习成果存证：链上锚定相对于中心化可验证日志的必要性边界》
- 英文：*When Is On-Chain Anchoring Necessary? A Decision Criterion for Educational Credential Integrity vs. Centralized Verifiable Logs*

**一句话研究问题（改造后的版本）**
在什么**威胁模型与信任假设**下，链上哈希锚定相对于"中心化 append-only log + 公开审计 + 数字签名"（如 Certificate Transparency / Sigstore / 透明日志）是**必要的**？在教育场景中，这些条件是否满足？

**为什么原方案（"基于区块链的教育大数据可信处理模块"）必须砍掉**

依据 F9，这是**教科书级的"技术找问题"**：

1. **领域已经提案雪崩**：Choudhury et al.（*Multimedia Tools and Applications* 84(8): 4003–4048, 2025）用 PRISMA 评估了 **150 个模型，其中 124 个已经是原型/试点/完整实现**，结论原文：*"an avalanche of proposals"*、*"scalability issues, poor overall performance, and increased price are major limitations"*。
2. **收益不明已被自家综述承认**：另一篇区块链教育系统综述的原文：*"It is unclear in some cases whether a DLT/Blockchain solution is an improvement over a more traditional, centralized ledger."*
3. **四大结构性障碍**（2026 年 e-learning 区块链综述）：可扩展性三难、监管模糊（GDPR 删除权 vs 不可篡改：这是**法律层面的硬冲突**，不是工程能解决的）、采用就绪度与技能缺口、术语不成熟。
4. **领域已经转向 W3C Verifiable Credentials + DIDs**，且共识路径是"法律承认 + 标准合规 + 小规模试点"——**这在个人博士项目（无经费、无机构授权、无法律承认）的资源约束下完全不可达**。
5. **与博士论文主线正交**：它不回答任何关于"学习如何发生"或"系统如何决策"的问题，会稀释故事线。

**若必须保留（导师/项目硬性要求），唯一的活路**

把论文从"我们做了一个区块链教育系统"改造成**"我们回答了区块链文献不愿回答的问题"**：

- **C1（形式化）**：给出威胁模型的形式化，并证明一个**判定定理**（或强猜想 + 论证）：当且仅当"验证方与签发方之间不存在共同可信第三方，且验证方之间需要互不信任地就记录状态达成一致"时，链上锚定才比中心化 append-only log + 公开审计产生**额外的**完整性保证。
- **C2（实证）**：在教育场景的具体信任拓扑下（学校签发 → 用人单位/其他学校验证），逐条检验该条件是否被满足。**预期结论：不满足**（学校与验证方之间存在教育部/考试院/学信网等可信第三方）。**这是一个阴性结果，但它是一个有价值的阴性结果。**
- **C3（量化对比）**：在成本、延迟、验证时延、抗篡改能力（在明确威胁模型下）、GDPR 删除权合规成本五个维度上，定量对比三种方案：(i) 中心化 DB + 签名；(ii) Merkle tree + 周期性公开锚定（**注意：这个方案一行区块链都不需要，却能拿到 ≈90% 的防篡改收益**）；(iii) 联盟链 / 公链锚定。
- **C4（落地）**：给出方案 (ii) 的完整实现与在 LearnFlow 上的部署测量。

**这个改造版本的价值**：它是一篇**诚实的、有阴性结论的系统性论文**，且与主线（数据可信性）能挂上钩。但它仍然：

- 大概率得出"教育场景不需要区块链"的结论，**会与出资方/导师的期待冲突**

## 2.7 【P7】系统论文：降级为 artifact，不计入核心论文

**结论：不写独立的"LearnFlow 系统期刊论文"。**

**理由**：六篇中唯一会 100% 命中"系统论文陷阱"的形态就是它。典型拒稿理由：*"This is an engineering report, not a research paper. The authors describe a system they built but do not answer a research question."*

1. **投一篇 6–8 页的系统描述短文**到 **JOSS**（Journal of Open Source Software）或 **SoftwareX**（Elsevier，非 CCF，SCI Q3–Q4）。目的不是学术贡献，而是：
   - 给 P1–P5 提供**可引用的 artifact**（审稿人要求复现时可指向它）
   - 给博士论文提供"系统实现"章节的发表背书

2. **开源 release + 完整 artifact**：代码、统计脚本（尤其是 P4 的 60/53 机制统计脚本）、数据集索引、Docker 镜像。
3. **在博士论文本体中写完整的系统章节**（这是学位论文的合法位置，期刊不是）。

**位置**：在 P1 与 P4 之后（需要有可展示的东西时），不占用投稿序列的关键路径。

## 3.2 依赖的**性质**（不只是箭头）

| 关系 | 性质 | 若上游延期的后果 |
|---|---|---|
| P2 → P3 | **强依赖（地基）**。P3 的模拟器直接由 P2 的剂量-反应曲线驱动。P2 还决定了"目标错误率是多少"，这反过来**约束 P1 的目标点** | P3 无法启动。这是规划中**唯一真正的强依赖** |
| P1 → P3 | **中依赖**。P3 的动作空间度量由 P1 定义。若无 P1，P3 仍可用 IRT 难度作动作空间（次优但可行） | P3 可降级执行 |
| P1 → P5 | **中依赖**。P5 需要"难度"的公共载体作为 ground truth 坐标系 | P5 可用 IRT β 直接作 ground truth（次优） |
| P3 → P5 | **中依赖**。P5 的 C3（决策层影响评估）需要 P3 的 bandit 框架 | P5 降级为纯相关性研究 → **应放弃 P5** |

| P1 ↔ P2 | **反向校准关系**（非单向依赖）。P2 若发现最优错误率 ≠ 15.87%，P1 的目标点必须相应调整。**建议二者并行，共享 IRT 拟合代码** | 需要一次结果对齐会议 |

**这个结构就是"故事线"的骨架**：**测量 → 目标 → 决策 → 先验 → 治理**，是一条逻辑链，不是五个散装工作。

# 4. 博士论文的"故事线"

## 4.1 统一研究故事

> **过去的二十年，自适应学习系统的研究把几乎全部精力投在了"把学生答对下一题的预测做得更准"上——pyKT 用 21 个深度模型 × 9 个数据集把这条路走到了尽头，却发现模型之间"分歧极小"、AUC 报告互相矛盾。
> 但一个更根本的问题从未被问过：这些系统所共同依赖的那个核心量——**难度**——究竟是不是一个被良好定义的可测量对象？
> 在一个真实的、有 60 个游戏化引擎的 K12 平台上，我们看到了答案的样子：三套来源不同、量纲互不相容的"难度"被一个没有任何实证依据的硬编码权重（0.45/0.35/0.20）线性相加；相加的结果被用作一次 SQL 精确等值匹配去筛选题目；而这个匹配所服务的目标值 85%，来自一篇只在人工神经网络和动物学习的二分类任务上验证过、作者本人明确表示"可能不适用于学生"的论文。
> 本论文论证：自适应学习系统的核心失败，不在于预测不够准，而在于**难度这个被所有组件共享的核心量，从未被当作一个可测量、可校准、可决策、可治理的形式对象来对待**。
> 我们因此做了五件事：为它建立测量论（P1）；检验它的目标值是否成立（P2）；把它嵌入序贯决策（P3）；审计替代性先验的质量边界（P5）；以及最后——当系统里有 60 个基于它做出来的、互相打架的行为干预时——为它们建立形式化与仲裁（P4）。**

## 4.2 Thesis Statement（论点陈述）

> **"自适应学习系统的核心失败不在于预测不够准确，而在于『难度』这个被所有组件共享的核心量从未被当作一个可测量、可校准、可决策、可治理的形式对象；本文通过建立难度的统一测量理论、以大规模真实学习者日志检验其最优目标值的外部效度、将其嵌入带记忆状态的序贯决策框架、并为由它派生的行为干预建立形式化治理，使自适应学习从『参数拼接的工程』转变为『可审计的测量与决策科学』。"**

**一句话版**：

> **把自适应学习系统中的"难度"从工程参数提升为可测量、可校准、可决策、可治理的一等公民。**

## 4.3 这个故事对 CS 哪个子领域做出贡献？

**定位：跨领域交叉，但主锚点明确。**

| 层次 | 归属 | 说明 |
|---|---|---|
| **主锚点 · 方法论身份** | **教育数据挖掘 / 学习分析（EDM / LA）** | P1/P2/P5 的方法核心是心理测量学 + 因果推断 + 大规模日志分析。这是最诚实的方法论身份 |
| **主锚点 · CCF 分类** | **数据库 / 数据挖掘 / 内容检索** | 投稿的 CCF 分区主要落在这里（TKDE / KAIS / IPM / Information Sciences）。**这是最现实的 CCF 归属** |
| **次锚点 · CCF 分类** | **人机交互与普适计算（用户建模与自适应交互）** | P4 的归属（UMUAI / IJHCS / TOCHI / CSCW）。P4 是"用户建模 + 自适应交互系统"的正统话题 |
| **方法论工具来源** | 心理测量学（IRT / 表示论）+ 因果推断（离策略评估 / 敏感性分析）+ 序贯决策（bandit / MDP）+ 软件工程（形式化 / 静态分析） | 这些是**借来的工具**，不是我们的贡献领域。**论文中不应对这些工具本身主张贡献** |
| ❌ **不应定位到** | **HCI 主赛道（CHI）** | CHI 要求用户研究（访谈、民族志、参与式设计）。**无经费、无用户、无 IRB 的条件下玩不起。** P4 的 E4（n≈60–120 感知指标）是极限 |
| ❌ **不应定位到** | **分布式系统 / 区块链** | 与主线正交（这正是砍掉 P6 的核心理由之一） |
| ❌ **不应定位到** | **深度学习 / 知识追踪** | 该赛道已被 pyKT 关闭（F3） |

**最简洁的领域署名建议**：
> "本研究位于**教育数据挖掘（EDM）**与**用户建模与自适应交互（UMUAI 谱系）**的交叉，方法论上借鉴心理测量学与因果推断。"

这个定位的好处：
- 它**避开了所有我们没有资源竞争的赛道**（CHI 的用户研究、TKDE 的系统工程、NeurIPS 的模型创新）
- 它**利用了 CCF-B 分区中最友好的两本刊**（KAIS / UMUAI）
- 它**与项目的真实能力匹配**（大规模日志分析 + 形式化建模 + 静态分析，都不需要钱和用户）

# 5. 关键战略建议

## 5.1 最锋利的 1–2 个 novelty

### 🥇 第一锋利：**P2 —— 85% 规则在真实学习者身上的大规模外部效度检验**

**为什么是它**：
1. **问题不是我找的，是 Nature Communications 作者亲手划的界**（F2）。Wilson 本人说 "probably won't apply directly to students"、"More research is going to be needed… outside of computer algorithms"。这不是从文献缝隙里硬挖的 gap。
2. **验证域极窄**（F1）：二分类、无提示、无跳过、无遗忘、无多知识点迁移。真实学习场景**五条全不满足**。
3. **结果无论正负都是贡献**：成立 = 首次大规模人类验证；不成立 = 对一个高引理论的干净修正。**这是博士生能得到的最好风险结构**——因为阴性结果也可发表（配合预注册）。
4. **零依赖、零自有用户**：三个公开数据集，千万级交互。
5. **规模优势可正面打**：对照 F7/F8（该领域多数研究 n=7～252），P2 的样本量高出 **4–5 个数量级**。这个对比本身就可以写在 Introduction 里。

**如果只能保一个，保 P2。**

### 🥈 第二锋利：**P4 —— 多干预引擎的冲突检测与干预预算仲裁**

**为什么是它**：
1. **它是六篇中唯一一篇"只有 LearnFlow 能写"的**。其他系统机制太少（3–8 个），暴露不出这个问题。**护城河最深。**
2. **它把项目最大的黑历史转化成了最强的可信度担保**：76 vs 60 vs 53 的数字差异，主动自曝 + 作为方法验证案例，比被揭穿强一万倍。
3. **FOMO 引擎 vs 防沉迷 vs 劝退休息的三方语义对立，是一个教科书级的可发表观察**。一个系统同时跑着互相抵消的行为干预——这个观察本身就有价值。
4. **它绕开了该领域最大的坑**：不做机制消融（样本量不可能），不声称任何机制对学习有效。
5. **零依赖**：与 P1/P2/P3/P5 完全独立，无传导风险。

### 为什么这两篇互补

- **P2 向外**：检验一个经典理论 → **学术合法性**
- **P4 向内**：形式化一个工程现实 → **独占性资产**

一个给论文"高度"，一个给论文"独有性"。**这两篇定了，博士论文的骨架就稳了。**

## 5.3 "0 真实用户数据"的破解思路

**核心判断：这个致命问题不是"能不能发论文"的问题，而是"必须彻底重写论文的方法学身份"的问题。**

### 破解策略一：严格区分三类"数据"，并精确措辞

| 类别 | 是否有 | 能否用于论文 | 论文中的精确措辞 |
|---|---|---|---|
| **① 公开真实学习者数据** | ✅ 有（ASSISTments / EdNet / Junyi / Anki FSRS logs） | ✅ **完全可以** | "real learner interaction data from publicly available datasets (N = X)" |
| **② 自有系统的真实部署数据** | ❌ **0 行** | ❌ 不能 | **绝对禁止**出现 "our deployment data"、"real users of our system"、"in-the-wild evaluation" |
| **③ 自有系统的静态可分析资产**（代码、机制清单、架构） | ✅ 有（16,593 行、60 引擎） | ✅ **可以，但只能用于静态分析类研究** | "static analysis of a production-scale gamified learning platform (16,593 LOC, 60 mechanisms)" |

**关键措辞纪律**：**"real learner data"（真实学习者数据）≠ "our deployment data"（我们的部署数据）。** 前者我们有（千万级，公开的），后者我们没有。论文中只用前者，且措辞必须精确到让审稿人无法误解。

### 破解策略二：哪些论文可以完全不需要自有用户

| 论文 | 数据需求 | 是否需要自有用户 | 关键技巧 |
|---|---|---|---|
| **P1** | 公开学习者日志 + Anki 复习日志 | ❌ **完全不需要** | 标定实验 + 合成重参数化实验 + 离策略回放 |
| **P2** | 公开学习者日志（3 个数据集） | ❌ **完全不需要** | **IRT 事前错误率 + DR 离策略评估**（核心技术） |
| **P3** | P2 产出的模拟器 + 公开日志 | ❌ 不需要（但需模拟器验证） | 模拟器 + 离策略 + **必须做 simulator validation** |
| **P5** | 公开题库 + 公开日志（ground truth） | ❌ 不需要（**除非用自有题库，则需其响应数据**） | 多模型标注 vs IRT ground truth |
| **P4** | LearnFlow 代码 + 外部项目代码 + **可选的 n≈60–120 真人** | 🟡 **E1–E3 不需要；E4 需要少量** | **E4 只测近端感知指标**（干预负荷、骚扰感、SUS），**不测学习增益** |

**结论：5 篇中有 4 篇（P1/P2/P3/P5）完全不需要自有用户，1 篇（P4）只需要 n≈60–120 的近端感知实验。**

### 破解策略三：三个必须掌握的方法学武器

**武器 1：IRT 事前错误率（P2 的核心）**
- **问题**：直接用观测正确率作"错误率"会引入能力混淆的内生性
- **解法**：在全样本上拟合 IRT（item-split 交叉拟合防泄漏），计算**作答前可知**的预测正确率 `p̂ᵢⱼ = σ(θᵢ − βⱼ)`，则事前错误率 `eᵢⱼ = 1 − p̂ᵢⱼ`
- **意义**：这个量在给定 (θᵢ, βⱼ) 下与本次作答的随机扰动独立，可用于因果性的剂量-反应估计

**武器 2：双重稳健离策略评估（DR / AIPW）**
- **用途**：在没有在线 A/B 的条件下，用历史日志估计**反事实策略**的效果
- **双重稳健**：只要倾向模型或结果模型其中之一正确，估计就是一致的
- **必须做的事**：权重截断（clipping）、报告有效样本量（ESS）、阴性对照结局、E-value 敏感性分析

**武器 3：模拟器 + 模拟器验证（P3 的关键，也是最容易被抓的地方）**
- **构建**：用 P2 校准出的剂量-反应曲线 + IRT 参数 + FSRS 记忆模型
- **验证（不可省略）**：用留出数据检验模拟器的预测误差（下一题正确率分布、掌握速度分布、反应时分布）
- **诚实报告**：如果模拟器误差大，就明说，并把结论的置信度相应下调。**审稿人的必杀技是"你的模拟器是循环论证"，唯一的防御是主动做验证并诚实报告。**

### 破解策略四：P4 的 E4 真人实验 —— 最紧急的非论文工作

**这是整个计划中唯一必须有真人、且无法通过任何方法学技巧规避的部分。**

| 项 | 建议 |
|---|---|
| **样本量** | n ≈ 60–120。**依据**：F8 显示该领域最好的实证是 n=252（只测任务绩效）；n=60–120 对**近端感知指标**（效应量通常较大，d≈0.4–0.7）可行 |
| **测什么** | **只测近端指标**：干预负荷感知（Likert）、骚扰感、SUS 可用性、感知相关性、退出率 |
| **不测什么** | **不测学习增益、不测长期留存**。理由：真实学习增益的效应量 d≈0.1–0.3，n=200 也测不出来（对照 F8：n=252 也只测出任务绩效） |
| **周期** | 2–4 周 |
| **获取渠道（按优先级）** | ① 本校一门本科/研究生课程的课程作业系统；② 与合作 K12 学校的信息技术课；③ 校内招募（**不建议 Prolific 等众包做 K12 场景，有伦理问题**） |
| **前置期** | **IRB / 伦理审查需提前 3–6 个月启动** |
| **时间窗口** | **必须在博士第 1–2 年内完成**，且最好对齐一个完整学期 |
| **风险** | 若招不到人：**E1–E3 已足以支撑一篇 CCF-B 论文**，E4 是冲 CCF-A 的加码，不是必需 |

**⚠️ 最紧急的提醒：E4 的 IRB 与招募前置期是 6 个月，但 P4 排在投稿序列第三。这意味着"立即启动前期准备"与"第三投稿"不矛盾——如果现在不启动 IRB，第 12 个月时 E4 就不可能完成。**

### 破解策略五：一个必须同步修的工程缺陷（给 data-engineer 的紧急请求）

即便 P1/P2/P5 全部用公开数据，**`attempts` 表的结构缺陷会在未来毁掉任何基于自有数据的复现**：

| 缺陷 | 后果 | 必须补的字段 |
|---|---|---|
| 无会话 ID | 无法重建学习序列、无法计算会话级干预预算 | `session_id` |
| 无展示/作答时间戳分离 | **无法计算反应时**（P3 心流通道的维度 2 需要它）、无法计算思考时长 | `presented_at` + `answered_at` |
| 无跳过标记 | 无法区分"不会"与"放弃"，会污染错误率估计 | `skipped` |
| 无干预上下文 | 无法做干预归因、无法审计干预账本（P4 的 C4 需要） | `active_interventions`（当次生效的 mechanism_id 列表） |

**这四项不补，LearnFlow 永远无法产出可发表的自有数据。这是比任何一篇论文都更基础的工作。**

## 5.4 现实性判断：个人博士项目（无经费、无大规模部署）

### ✅ 现实的（一台工作站 + 公开数据即可）

| 项 | 理由 |
|---|---|
| **P1** | 纯离线。IRT 拟合 + Platt 标定 + 合成实验。计算量可控（千万级交互的单机 IRT 拟合可行） |
| **P2** | 纯离线。**六篇中最现实的一篇**。三个公开数据集 + 单机统计计算。无 IRB、无招募、无部署 |
| **P3（理论 + 模拟器部分）** | 理论适配 + 模拟器。计算量可控 |
| **P4（E1–E3）** | 静态分析 + 跨项目复现 + 账本一致性检查。**零用户、零经费** |
| **P5**（若 go/no-go 通过） | LLM API 调用有成本（需预算数千元级），但相对可控；其余离线 |
| **P7（JOSS/SoftwareX）** | 开源 release + 短文 |

### 🟡 半现实的（需要额外资源但可争取）

| 项 | 需要的资源 | 争取路径 |
|---|---|---|
| **P3 的在线 A/B** | 真实部署 + 用户流量 | 与一所学校/一门课程合作；或放弃，诚实声明只有离策略评估 |
| **P4 的 E4** | n≈60–120 真人 + IRB | 本校课程 / 合作学校。**前置期 6 个月** |
| **P1 的 Anki 日志** | 数据集可获取性 | **第 1 个月内确认**；若不可得，砍掉 FSRS 源的实证 |

### ❌ 幻想（在个人博士资源约束下不可行，应尽早放弃）

| 幻想 | 为什么不可行 |
|---|---|
| **53 个机制的消融实验** | 样本量需数千；该领域最好的实证是 n=252 且只测任务绩效（F8） |
| **n ≥ 500 真实 K12 用户的 RCT** | 无经费、无部署、IRB 难、招募难 |
| **任何声称测出"长期学习增益"的实证研究** | 真实学习增益效应量 d≈0.1–0.3，n=1000+ 起步，且需要跨学期追踪 |
| **区块链模块的实际部署与机构采纳** | 无机构授权、无法律承认。领域共识是需要"法律承认 + 标准合规 + 小规模试点"（F9），个人项目一条都不具备 |
| **冲刺 CCF-A（TKDE / TOCHI）作为主路径** | 录用率与周期对博士生极不友好；应作为 stretch goal |
| **"76 机制"的说法蒙混过关** | 审稿人一查 GitHub 即穿，且会连带质疑所有其他数字 |

### 给主理人的资源配置建议

1. **把 80% 的时间投在 P2 和 P4 上** —— 这两篇是六篇中总分最高（22、20）、依赖最少（都是零依赖）、且一个给"高度"一个给"独有性"的。
2. **P3 先投会议版** —— 会议周期短、反馈快、可迭代，期刊版再标 "extended version"。这是博士生做重方法学工作的最优路径。
3. **P5 设置 go/no-go** —— 不要投入超过 2 个月在前置验证上；若题库无响应数据或结果纯正面，立即止损。
4. **第 1 个月内完成三个检查点**：① Anki 日志可获取性（P1）；② LearnFlow 题库是否有响应数据（P5）；③ `attempts` 表改造排期（对所有未来工作）。
5. **第 1 个月内启动 P4-E4 的 IRB 前期** —— 6 个月前置期，错过就要再等一个学期。
6. **P2 的预注册必须在接触数据前完成** —— 这是本篇方法学可信度的基石，也是阴性结果能发表的前提。
