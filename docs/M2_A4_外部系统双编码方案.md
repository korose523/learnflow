## 3. CODEBOOK（编码字段与判据）

每个被编码的"机制实例"须带 **`file:line` 锚点**（可复现性硬要求，与 M2 全文一致）。

| 字段 | 类型 | 允许取值 | 定义 | 示例 |
|---|---|---|---|---|
| `target_construct` | 名义 | `reward / nudge / reminder / badge / notification / prompt / …` | 该代码点意图触发的**行为科学构念**（与 LearnFlow 注册表类别对齐） | `score.php` 加分 → `reward` |
| `direction` | **有序** | `withdraw < neutral < approach` | 干预的语义方向：`approach`=拉回加时/促学，`withdraw`=推开休息/保护，`neutral`=中性 | 限时提醒 → `approach`；强制休息 → `withdraw` |
| `channel` | 名义 | `notification / badge / point / streak / leaderboard / …` | 干预落地的**载体/通道** | 徽章弹窗 → `badge` |

**编码规则**
- 一个"机制实例"= 一处会向用户产出可见/不可见干预的代码点（函数或配置项），对应一个 `item_id`。
- `direction` 是**有序**字段，故 κ 用线性加权（见 `external_coding_kappa.py` 的
  `cohen_weighted_kappa`，权重 `w=1-|i-j|/(K-1)`，`withdraw=0, neutral=1, approach=2`）。
- 每个编码必须附 `source_anchor`（如 `classes/local/gameelements/score.php:42`），无锚点不计。
- `target_construct` / `channel` 为名义字段，用简单 Cohen κ。

> ⚠️ **原 §3 CODEBOOK 已废止（自 2026-09-26 起）**：其 `target_construct` 允许取值写为英文
> （reward/nudge/reminder/badge/notification/prompt…），且**把 channel 词（badge/notification）混入了 construct 列**，
> 而 coderA/coderB 实际都用中文（身份/自主、成就/表现…）——标签集既不闭集、又中英文脱节，
> 是 `target_construct` κ 被压到 0.346（见 §8）的结构性根因。请以 **§3.1 修正版闭集 CODEBOOK** 为准。

## 4. 双编码流程

1. **抽取单元**：对 ≥4 个系统各自抽取机制实例清单（item_id 全集由两名编码者共用）。
2. **独立编码**：两名编码者（coderA / coderB）**互不知晓对方结果**，各自填一份 CSV
   （列：`system, item_id, target_construct, direction, channel, coder, source_anchor`）。
3. **计算 κ**：`python results/m2/external_coding_kappa.py --coder-a coderA.csv --coder-b coderB.csv`
   → 输出各字段 κ（direction 为加权）。
4. **信度门槛**：κ ≥ 0.61 实质一致；0.41–0.60 中等（可接受，须报告）；< 0.40 较差
   → **须回看编码方案、重编码该字段**，直至 ≥ 0.41。
5. **分歧消解**：κ < 0.41 的字段，两名编码者就分歧项协商或请第三名仲裁，记录决议。
6. **报告**：在 M2 稿 §6 增补"双编码 κ 表"（每系统 × 每字段的 κ 与 %一致），并注明
   单编码升级为双编码的系统（Ludilearn/Level Up XP）。

### 11.4 κ 复算脚本（33 项口径）

`results/m2/a4_kappa_v3.py`（相对 v2 的三点强化）：

1. 以 `a4_items_all.csv` 为**题项全集**做覆盖检查——缺项 / 越界项 / 系统名不一致全部报出，不静默丢弃；
2. **闭集校验**：任一侧出现 §3.1 闭集外取值即报错并定位（v2 允许自由中文词，正是 κ 被压到
   0.346 / 0.452 的结构性原因）；
3. 除总体 κ 外**分系统报告 κ**（A4 的外推性论证须按系统看，而非只看汇总）。

```
python results/m2/a4_kappa_v3.py --coder-a a4_coderA_survey_v2.csv --coder-b a4_coderB_survey_v2.csv
python results/m2/a4_kappa_v3.py --selftest   # 17 项旧卷自检
```

**自检结果（2026-09-27）**：`--selftest` 精确复现 17 项闭集值 0.778 / 0.595 / 0.935，
证明 v3 与 v2 的 κ 数学一致、对齐逻辑无误，可直接用于 33 项回收数据。

**自检顺带暴露的一处分系统事实（须在稿中如实报告）**：direction 的总体 κ=0.595 由
Level Up XP 单独支撑（LUXP 分项 0.744），**Ludilearn 分项的 direction κ=0.000**——
该子系统仅 6 项、direction 分布高度集中（5 项 approach），κ 在小 n + 边际同质时被压到 0。
这不是编码冲突的证据，而是**分项 κ 在小 n 下不稳定**的示例；因此投稿时应
**同时报告总体 κ 与分系统 κ**，且不得只挑好看的分项报。

> **须在稿中披露的方法学限制**：33 个题项的"功能描述"由自动化的源码阅读遍生成
> （非编码者本人读源码），两名编码者基于同一组描述作答。这属于**文档摘要式双编码**，
> 它检验的是 CODEBOOK 的构念效度（同一证据能否被不同人映射到同一码），
> 而非编码者各自读源码的一致性。锚点全部 pinned 且公开可核，读者可自行复核。
