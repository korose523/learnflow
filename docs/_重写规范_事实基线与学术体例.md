## 第二部分 · 学术写作体例（期刊论文 / 博士论文统一标准）

### 2.1 语言与语域

- 中文学术书面语，**禁止**博客/口语/营销表达：不得出现"结论先行""一句话结论""血泪建议""诚实说""最锋利的""翻车""坑"等；
- **禁止**使用 emoji（⭐ 🔴 ✅ ⚠️ 等）作为语义载体；
- 判断性内容**保留**，但改用学术措辞（例："这个数字不成立" → "该数值与可复算实测值不符，差异来源见表 X"）；
- 首次出现的术语须给出英文原文并下操作化定义（例："心流通道（flow channel）……本文将其形式化为……"）。

### 2.2 结构

- 三级编号：`1` / `1.1` / `1.1.1`；
- 每章开头写**本章摘要**（80–150 字），章末写**本章小结**（3–5 条要点）；
- 全文开头写**摘要**（200–300 字）+ **关键词**（4–6 个）；
- 文档末尾视需要设**附录**（机制全表、复算命令、符号表）。

### 2.3 主张—证据耦合（本项目最强约束）

每个实证性论断之后必须标注证据类型之一：

- **代码证据**：`app/services/xxx.py:123`（行号必须真实，写前请核实）；
- **复算证据**：标注命令，如「复算命令：`python scripts/verify_counts.py`」；
- **文献证据**：`[@citekey]`。

**禁止**无源断言："研究表明""众所周知""显然""学习科学表明""业界公认"等一律删除或补源。

### 2.4 引用规范

- 统一 `[@citekey]` 形式；
- 键必须存在于 `E:\learnflow\docs\references.bib`；
- **严禁凭记忆编造文献**（作者、年份、期刊、DOI）。若确实需要而 bib 中没有，写 `[@待核验:作者年份]` 并在文末「待核验引用清单」中单列；
- 参考文献表按作者—年份排序，中文文献在后。

### 2.5 图表规范

- 表/图必须编号 + 标题：**表 3-2 机制分类学一览**、**图 4-1 三层漏斗仲裁流程**；
- 正文必须显式引用（"如表 3-2 所示……"），不得出现孤立图表；
- 表格一律用 Markdown 管道语法；
- 任何含数字的表格下方加一行：> 复算命令：`…`（输出：`artifacts/xxx.json`）。

### 2.6 篇幅与诚实性

- 重写后篇幅**不得少于原文档**（原行数由主理人在任务书中给出）；
- 局限、效度威胁（threats to validity）、否定性结论必须单列小节如实陈述；
- 不得通过删减内容来"达标"；不得为让数字好看而调整口径。

### 2.7 交付要求

- 只写文件，**不要执行 git commit**（由主理人统一提交）；
- 完成后向主理人报告：① 文件路径与新行数；② 修正的陈旧数字清单（旧 → 新）；③ 新增的「待核验引用清单」；④ 未能核实的事项。
