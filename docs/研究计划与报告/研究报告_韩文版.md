## 초록

본 보고서는 "난이도"를 핵심 대상으로 삼는 적응형 학습 연구의 완료된 작업을 종합한다. 연구는 실제로 구축되어 오픈소스로 아카이브된 K12 게이미피케이션 적응형 학습 플랫폼(게이미피케이션 개입 메커니즘 **등록 54개**, 번호 LF-M01…LF-M54, 그중 **런타임에서 실제로 개입 효과를 생성하는 생산자는 2곳**(LF-M44 / LF-M52)뿐이며 **성숙도 분포는 complete 9 / partial 37 / placeholder 8**; 학습 방법 **28종**; 메커니즘 레지스트리 지문 `ee1a49be5732`; 백엔드 **88개 파일 / 25,795행**; 접근 가능한 API 엔드포인트 **104**개; 전체 테스트 **54개 테스트 파일 / 936건 통과**; Zenodo DOI `10.5281/zenodo.22719229`)에 의존한다. 보고 기간 내에 세 편의 지원 논문의 전체 실험을 완료하고 완성 원고를 작성하였으며, 융합 추정기의 최적화와 구현 반영을 완료하고 백엔드 지표의 재계산 가능 게이트를 구축하였다. 세 가지 주요 결론은 다음과 같다. 난이도 선형 정규화 가중 하에서 유효 가중치는 불안정하며, 분위 공척도로 전환한 후 드리프트가 L1 = **0.5357**에서 0.0001로 감소하였다. 다중 신호 융합의 이득은 예측력 향상이 아니라 **전문가 라벨과의 일치도 이득**이며, 판정기준 전환 후에는 전면적으로 부(負)로 반전된다. 개입 7-튜플에 대한 정적 감사는 **분류 불가 비율 77.8%**를 보였고, 그 직접 원인은 7-튜플의 네 필드가 코드에 아직 구현되지 않았다는 것이므로, 이 결과는 **구현 완성도의 진단**으로 규정하며 반증 조건이 발동한 일반적 "발견"으로 규정하지 않는다. 본 보고서는 이에 따라 "충돌은 보편적이지 않다"라는 외삽성 표현을 철회한다. 보고서는 동시에 부정적 결과와 정직한 격차 목록을 사실대로 열거하며, 그중 인과 측 식별과 인간 피험자 실험은 아직 실행되지 않았고 이는 본 연구 다음 단계의 주된 과제이다.

**주제어**: 적응형 학습; 난이도 측정; 공약성; 판정기준 의존성; 콜드 스타트 정렬; 다중 개입 거버넌스; 부정적 결과

### 2.2 수치 정직성 게이트

시스템에는 역사적으로 메커니즘 집계의 표현 팽창이 나타난 적이 있다. 보고 기간 내에 4계층 재검증을 완료하고 머신 게이트를 구현하였다.

| 계층 | 산출 기준 | 집계 |
|---|---|---:|
| L0 | 초기 문서 제목의 주장 | 76 |
| L1 | PRD 표의 항목별 합산 | 69 |
| L2 | 구현 단위(`mechanism_units`) | 60 |
| L3 | 의미 중복 제거 후 고유 메커니즘 | **54** |

차액 22 = 76 − 54는 다음과 같이 분해된다. 7(제목의 근거 없는 부풀림) + 9(표에 혼입된 비메커니즘 항목) + 6(엔진 간 중복 구현).

**엔지니어링 구현.** 리포지토리 내에 두 개의 주 게이트 스크립트를 제공한다. `verify_counts.py`는 권위 집계와 교차 검증을 수행하고, `verify_asset_numbers.py --doc-check`는 문서 수치와 코드 사실이 불일치할 때 종료 코드 1로 실패한다. v1.1에서 세 개의 보조 게이트를 추가하였다. `results/code/verify_window_support.py`(슬라이딩 윈도 분포의 21개 이산 지지점을 고정하고 구 등폭 분할 필드의 회귀를 금지), `results/m2/verify_m2_anchors.py`(동결 tag에서 감사 시점 트리를 읽어 효과 생산자 2곳과 중재기 방향 표를 검증), `results/code/o13_llm_protocol_audit.py`(프로토콜 가용성 등급과 짝지음 bootstrap). 본 보고서의 모든 수치는 위 게이트를 통과하였다.

**메커니즘 계수 삼중값(v1.1 신설 기준).** `verify_counts.py`는 권위 집계를 출력하는 동시에 **등록 54 / 효과 생산 2 / 성숙도 complete 9·partial 37·placeholder 8**을 병기 출력하여, "등록 메커니즘 수"와 "런타임에서 효과를 생성하는 메커니즘 수"가 문서 유통 과정에서 하나의 수치로 합쳐지지 않게 한다. 본 보고서는 메커니즘 수량이 등장하는 모든 지점에서 이 삼중값을 사용한다.

> 재계산 명령: `python scripts/verify_asset_numbers.py --doc-check`
> **자산 지표의 "문서 측 ↔ 실측" 관계(v1.1 정정, 이번 개정에서 검증 완료)**: `--doc-check`의 **문서 측 기준**은 `docs/LearnFlow_期刊论文拆分方案.md` §1의 자산 문장이다.
>
> - **현재 상태(2026-09-22 실측)**: 해당 문장이 등록한 값은 실측값 **25,795행 / 55개 서비스 모듈 / 88개 소스 파일 / 104개 API 엔드포인트 / 936건 테스트(54개 테스트 파일)**이며 코드 사실과 **항목별로 일치**하므로, 이 명령은 **종료 코드 0(통과)을 반환한다**. v1.0 보고서가 말한 "현재 종료 코드 1을 반환"은 **25,389 / 54 / 87 / 104 / 920(53개 테스트 파일)**을 등록한 초기 스냅샷 문장에 대응하며, 그 스냅샷은 이번 개정에서 실측에 맞추어 정렬되었다.
> - **드리프트 증거는 사라지지 않았고 위치만 바뀌었다**: **감사 시점의 등록 기준선**(`python_loc` 25,389 / `source_files` 87 / `service_modules` 54 / `test_files` 53 / `test_functions` 826 / `tests_collected` 920)은 **하드코딩 등록표** 형태로 `verify_asset_numbers.py`에 보존되어 있으며, 실행할 때마다 "등록 비교" 단락에서 `informative / drifted` 등급으로 **항목별 실측값과 나란히** 출력된다(`artifacts/asset_numbers.json`에 기록). 논문 2의 제4.4절이 바로 이것에 근거하여 자산 드리프트를 감사 발견으로 사실대로 기록한다.
> - **본 보고서의 처리 원칙**: 이 명령의 녹색 신호는 **판정 기준을 완화한 데서 온 것이 아니라**, 문서 기준선을 사실에 맞추어 갱신한 데서 온다. 그리고 "감사 시점 자산 지표가 현재 실측과 불일치한다"는 사실은 **동일한 출력의 등록 비교 단락에서 여전히 완전히 가시적이며**, 은폐하지 않는다.

### 3.4 방향성 오류의 특정과 표본 크기 적응적 수축

나아가 융합 구성 내의 실제적인 **방향성 오류** 한 곳을 특정하였다. 상승률과 전문가 라벨의 상관은 −0.1837, 풀 내에서는 −0.756인데, 좌표 상승 최적화기는 여기에 **+0.154의 양의 가중치**를 부여하였다. 해당 신호를 제거하고 표본 크기 적응적 수축을 도입한 후, 소표본 구간에서 처음으로 기준선을 역전하였다(k = 10일 때 +3.43 퍼센트포인트). 그러나 이득은 표본 크기가 커짐에 따라 빠르게 감쇠하여 k ≥ 100일 때 0.22 퍼센트포인트 이하가 된다.

**수축 규칙.** λ_cf(k) = 1 / (1 + (k/27.3)^0.895)(전량 적합값은 27.4 / 0.902, R² = 0.9989; 배포값은 leave-one-k 교차 검증 적합 결과를 취한다). 이 규칙은 **leave-one-k 교차 검증(구간 내삽)**으로 검정하였다. k ∈ {10, 50, 200}만으로 적합하고, 적합 구간 [10, 200] 내에서 k = 25 / 100을 평가하여 경험적 최적 이득의 111%와 128%를 보존하였으므로, **배포에 따라 재조정할 필요가 없다**. 이 결론은 학생 신원으로 분할한 **학생 수준 홀드아웃**에서 완전히 재현된다(k = 10일 때 전혀 조정하지 않은 추정이 +3.64 pp를 제시하며, 레코드 수준 홀드아웃의 +3.43 pp와 거의 일치한다).

### 3.5 추정기 최적화: "제거"에서 "부호 교정"으로

보고 기간 내에 융합 추정기의 두 가지 최적화를 완료하였다. 방향이 잘못된 신호를 **전체 열 제거**에서 **부호 교정**으로 바꾸고(음의 증거로 계상하여 그 정보를 보존한다), 각 신호를 적합 블록 내의 **반분 신뢰도**로 가중하여 `srw7` 추정기를 얻었다. 모든 부호, 가중치 및 수축 계수는 적합 블록 내에서만 추정되어 누출이 없다.

| 레코드 수준 홀드아웃 | **+3.823** / +2.025 / +0.930 / +0.391 / +0.138 |

### 3.7 최적 오류율의 기술적 증거와 인과 식별의 미완

> **본 절은 v1.1에서 전체 재작성되었다(2026-09-22 정정, 심사의견 §3.1 및 정정표 제1행). 종전의 "최빈 구간이 0.15–0.20(성공률 80%–85%)에 놓인다"는 표현은 검토 결과 **등폭 분할의 경계 인공물**로 판명되었으므로 폐기하며, 다시 인용되어서는 안 된다.**

**종전 표현이 인공물인 이유.** 윈도 폭 W = 20이므로 슬라이딩 윈도 오류율은 k/20(k = 0,…,20)의 **21개 이산 지지점**만 취한다. 종전 코드는 `np.histogram(win_err, bins=np.arange(0, 1.0001, 0.05))`로 20개의 등폭 구간을 만들었는데, 구간 경계가 이산 지지점과 정확히 겹치고 오류율이 `1 − (누적합의 차)/20`으로 계산되어 부동소수점 오차를 동반한다(k = 16은 0.19999999999999996, k = 17은 0.15000000000000002, k = 18은 0.09999999999999998). 그 결과 **0.15와 0.20이 동일 구간 [0.15, 0.20)으로 병합**되고, 0.10은 [0.05, 0.10)으로 떨어지며, **0.25는 [0.25, 0.30)에 홀로 남는다**. 이른바 "최빈 구간"은 **두 이산값의 합**인데 이와 비교되는 0.25는 **단일값**이므로 양자는 비교 가능하지 않다.

**정수 오류 개수로 재계산한 결과.** 이제 정수 오류 개수 k로 집계하고(`np.bincount`, 전 과정 부동소수점 비교 없음) 21개 지지점의 빈도를 보고한다.

| 통계량 | 값 |
|---|---|
| 윈도 총수 | 286,150 |
| 유효 사용 인원 | 아래 기준 설명 참조 |
| 평균 오류율 | 0.3511 |
| **단일값 최빈값** | **오류율 0.25(성공률 75%), 30,899 윈도, 10.80%** |
| 80–85% 성공률 구간 | 19.64% |
| 80–90% 성공률 구간 | 26.40% |
| 최빈값의 bootstrap 신뢰집합(학생 단위 재표집, 200회) | **{0.25}**, 재표집의 95.5%에서 출현 |

**이에 따른 세 가지 결론.**

1. **단일값 최빈값은 성공률 75%이며, 80–85%가 아니다.** 단일값으로 보면 "80–85% 성공률이 최빈값이다"라는 문장은 **저장된 결과와 불일치한다**. 오류율 0.25(30,899 윈도)는 오류율 0.15와 0.20 각각보다 많다(`share_err_in_17_23pct`로부터 역산하면 0.20 ≈ 30,074 윈도, 0.15 ≈ 26,138 윈도).
2. **종전의 "85% 규칙의 15.87% 및 선행연구의 80.7%와 모두 양립한다"는 문장은 성립하지 않는다.** 이 문장은 인공물 위에 세워져 있으므로 철회한다. 분포의 단일값 최빈값은 Wilson 등의 84.13%와 Baillifard 등의 80.7%보다 **낮다**. 특정 후보 최적값과 양립한다고 말하려면 "80–85% 구간의 윈도 점유율이 다른 어떤 5퍼센트포인트 폭 구간보다 높다"고만 말할 수 있으나, **이는 구간 폭 효과이지 최빈값 위치의 증거가 아니다**.
3. **종전의 "세 가지 필터 기준의 최빈 구간이 동일하다"는 강건성 주장도 성립하지 않는다.** 세 기준은 종전에 동일한 분할 함수를 재사용하였으므로 독립적 증거가 아니며, 그중 tutor_mode 기준의 윈도 수는 실측 0이었다. 본 판은 정수 오류 개수로 각각 재계산한 후 **세 기준의 일치를 더 이상 주장하지 않는다**.

## 5 논문 3: 유순 난이도 의사결정과 대규모 언어모델 난이도 사전확률의 신뢰성 경계

### 5.1 유순 행동 공간의 실증적 기초

자체 구축 시뮬레이터의 등거리 선형 난이도 가정을 Junyi의 실제 연습으로 대체하고, 행동 공간을 "동일 지식 strand 내에서 전문가 난이도로 그룹화한 실제 연습"으로 재구축하였다. Junyi의 전체 규모는 **16,217,311건 상호작용 / 72,758명 사용자 / 1,326개 연습**이며, 행동 공간 재구축에는 그중 전문가 라벨이 있는 부분집합을 사용하였다. 전문가 난이도 라벨의 경험적 성공률은 엄격히 단조이다.

| 전문가 라벨 | 경험적 성공률 |
|---|---:|
| easy | 0.7355 |
| normal | 0.6328 |
| hard | 0.6160 |

난이도 전이는 **등반 마찰**을 보인다. hard→easy는 0.7534, easy→easy는 0.7335인데, easy→hard는 0.6302에 불과하다. 하강 전이와 상승 전이의 차이는 **12.3 퍼센트포인트**이고, 같은 easy에서 출발한 두 전이의 차이는 **10.3 퍼센트포인트**이다. 이는 "행동 공간이 유순하고 전이가 비대칭"이라는 모델링 전제의 일차 행동 증거이다.

### 5.2 실제 팔에서의 전략 비교(보상 = 즉시 성공률): 예비 관찰이며 결론을 구성하지 않는다

> **본 절의 제목과 성격 규정은 v1.1에서 정정되었다(2026-09-22, 심사의견 §5.3).** 종전 제목은 "능력 사전확률 없이 능력 인지 전략의 수준에 도달"이었으나, 이 표현은 **자료가 지지할 수 있는 강도를 초과**하므로 삭제하였다. 핵심 원인은 **보상 정의**이다. 본 실험의 보상은 **즉시 성공률**이며, `flow_zone`은 바로 성공률 0.75를 겨냥하는 전략이므로 즉시 성공률을 보상으로 하는 실험에서 고득점하는 것은 **거의 동어반복**이다(`all_easy`가 고득점하는 이유와 같다). 학습 이득을 관측할 수 없는 데이터에서 전략 비교는 **예비 관찰**로만 취급할 수 있다.

52,733명 사용자로 표정하고, 500회 시뮬레이션 × T = 40, **보상 = 즉시 성공률**의 실제 팔 실험에서:

| 전략 | 점수(즉시 성공률) |
|---|---:|
| 능력 사전확률 정확 | 0.7023 |
| 능력 사전확률 반전 | 0.6714 |
| `flow_zone`(성공률 0.75를 겨냥, 능력 사전확률 불필요) | **0.7119** |

**말할 수 있는 것**: 능력 사전확률 정확과 반전 두 전략의 차이는 +0.0309(약 2.9σ)이며, 즉 **이 보상 정의 아래에서 능력 오판의 대가는 강건하게 양(正)이다**; `flow_zone`과 능력 인지 전략의 차이는 약 1σ(유의하지 않음)이다.

**말할 수 없는 것**: "능력 사전확률 없이 능력 인지 전략의 수준에 도달한다"로 서술할 수 없으며, 이를 근거로 "능력 모델링이 불필요하다"고 논증할 수도 없다. **이유**: 보상이 성공률일 때 성공률을 겨냥하는 전략이 우세한 것은 설계상 예상 가능하며, 본 실험은 "전략이 더 우수함"과 "보상 정의가 그 전략에 유리함"을 구분할 수 없고, 학습 이득·관측성·내생성(전략이 데이터로 생성되어 행동 분포가 무작위가 아님)도 포괄하지 못한다.

**엔지니어링 교훈(그대로 보존할 가치가 있는 실무 결론).**

- `format: json`은 **출력을 제약하기에 충분하지 않다**: 모델이 `{"explanation": ...}` 템플릿을 출력하여 파싱 실패율이 약 30%이다;
- JSON Schema의 **enum / array-enum** 제약을 사용하여야 한다;
- 정렬 과제는 자유 문자열이 아니라 **열거 배열**(예: `{"ranking":["A","B","D","C"]}`)을 사용하여야 한다.

**수정된 방법론 결론**: 인용 가능한 프로토콜(열거 배열)의 실측은 **48배치 / 0 파싱 실패 / ρ = 0.0478**이며, 다른 가용 프로토콜(열거 배열 + Bradley-Terry)은 **60배치 / 13배치 파싱 실패(21.67%) / 697건 제약 / ρ = 0.1553**이다. 따라서 말할 수 있는 것은 **출력 형식 제약(schema 유형)이 주석 가용성에 미치는 영향이 "절대 평정 대 상대 정렬"이라는 방법 선택과 동등하게 중요하다**는 것이며, **"프로토콜 강건성이 방법 선택보다 크다"고는 말할 수 없다** — 이 문장을 뒷받침하는 두 번의 실패 실행은 표본으로 삼을 수 없기 때문이다. 프로토콜 감사를 LLM 난이도 주석 실험의 **필수 보고 항목**으로 설정할 것을 권고한다.

### 8.3 산출 기준 정정 흔적

보고 기간 내에 수치와 산출 기준의 정정이 여러 차례 있었으며, 구값이 계속 인용되는 것을 방지하기 위하여 여기에 전부 흔적을 남긴다.

**정정 1: 난이도 공약성 계수.** 초기 일련의 드리프트 실험이 세 난이도 원천의 부호 약정을 혼용하였다(IRT 원천은 logit 정답률을 취해 양의 방향이 "쉬움"; 시간 길이와 시도 횟수는 원시값으로 양의 방향이 "어려움"). 이로부터 얻은 선형 융합 드리프트는 체계적으로 과대하게 산출되었다. "양의 방향 = 어려움"으로 통일한 뒤 재계산한 실제 드리프트는 **L1 = 0.5357**이다. 본 보고서는 이 산출 기준을 일률적으로 채택하며; 정정된 구 수치는 "더 높다"는 정성적 서술로만 등장하고 **결과로서 인용되어서는 안 된다**. 구 산출 기준의 산출물은 주 산출물에서 이전되었다: `results/code/real_data_results.json`은 더 이상 구 드리프트 블록을 보유하지 않고, 구 수치는 `results/code/deprecated/assist09_drift_v1_sign_mixed.json`으로 옮겨져 `_deprecated: true`로 표기되었다.

**정정 2: 슬라이딩 윈도 오류율 분포(v1.1 신설, 심사의견 §3.1).** 종전의 "최빈 구간 0.15–0.20(성공률 80–85%)"은 **등폭 분할의 경계 인공물**이다. 즉 분할 경계가 21개 이산 지지점 k/20과 겹치고 부동소수점 오차가 더해져 0.15와 0.20이 동일 구간으로 병합되었다. 정수 오류 개수로 재계산한 후 **단일값 최빈값은 오류율 0.25(성공률 75%, 30,899 윈도)**이며, bootstrap 최빈값 집합은 재표집의 95.5%에서 {0.25}이다. 종전 표현은 전문 폐기한다. 상세는 §3.7.

**정정 3: placeholder 메커니즘 수(v1.1 신설, 정정표 제2행).** 종전에는 placeholder 메커니즘을 **4**개(LF-M29 / LF-M32 / LF-M49 / LF-M50)로 기재하였으나, 실측 `mechanism_registry.py`에서 `maturity="placeholder"`는 **8**개(LF-M19 / LF-M28 / LF-M29 / LF-M32 / LF-M45 / LF-M49 / LF-M50 / LF-M53)이다. 구 기준은 4개를 누락하였으며 정정 완료.

**정정 4: 메커니즘 "구현 반영"의 의미(v1.1 신설, 정정표 제3행).** 종전의 "메커니즘 런타임 구현 반영 54 / 54, 고아 0"은 등록 항목과 구현 단위의 대응 관계가 완전하다는 의미이며, **54개 메커니즘이 모두 런타임에서 개입 효과를 생성한다는 뜻이 아니다**. 실측 프로덕션 환경의 효과 생산자는 **2곳**(LF-M44 / LF-M52)뿐이다. 이후 일률적으로 삼중값을 병기한다: **등록 54 / 효과 생산 2 / 성숙도 9·37·8**.

**정정 5: LLM 모델 정체와 프로토콜 design 문자열(v1.1 신설, 정정표 제6·7행).** 종전의 "qwen3-6B 규모"는 오류이다. 코드의 모델 라벨은 `qwen36` 하나뿐이고, 공식 Qwen3 dense 계열에는 6B 규격이 없다. 현 표기는 Ollama manifest + GGUF 헤더 파싱 결과인 **Qwen3.6-35B-A3B**(`qwen35moe`), 양자화 **IQ3_S**, manifest `sha256:5f2d8551…`이다. 또한 `llm_labeling_v2.json`의 `design` 필드는 "/no_think"로 표기되어 있었으나 실제 prompt와 API body에는 해당 표기가 사용되지 않았으므로, "JSON-schema 제약 디코딩, /no_think 미사용"으로 정정하고 `_design_correction` 필드로 흔적을 남겼다.

## 9 미완료 사항과 다음 단계 계획

**장 요약**: 본 장은 이후 두 단계의 주된 과제와 선행 사항을 제시한다.

### 9.1 2단계: 인과 측과 인간 피험자

1. **인과 식별 전략을 확정하고 흔적을 남긴다**(결과 변수에 접촉하기에 앞서). 이후 오프폴리시 용량—반응 추정과 다섯 전제 분해를 실행한다.
2. **의사결정 측의 두 가지 미실행 항목을 보완한다**: 추출가능성을 상태로 하는 구조적 예측, 앙상블 규모 임계값. 둘 모두 go/no-go 점검 지점이며, 먼저 타당성 폐루프를 수행해야 한다.
3. **윤리심의(IRB)를 착수한다**. 미성년자가 관련된 피험자 실험은 심의와 보호자 동의 절차의 선행 기간이 길며, 승인 취득 전에는 어떠한 인간 피험자 데이터도 수집할 수 없다.
4. **최소 실행 가능 피험자 실험을 수행한다**. 그 위치는 공개 데이터 결론에 대한 검증으로 하고, 주된 결론의 유일한 지지로 삼지 않는다.

### 9.2 3단계: 학위논문 통합

"측정에서 거버넌스로"의 통합 장을 작성하여 측정, 목표, 의사결정, 거버넌스 네 체인을 하나의 형식적 프레임워크로 통일한다. 시스템의 완전한 기술은 학위논문 본체에 둔다.

### 9.3 전파 계획

세 편 지원 논문의 완성 원고를 완료하였다. **저널 기준은 정정되었다(v1.1, 심사의견 §2.4)**: 대학원의 박사 졸업 요건은 **Scopus 수록 저널** 게재이므로, 세 편 모두 **영어 Scopus 저널을 제1순위**로, 중국어 저널을 제2순위로 하며 중국어 저널은 졸업 기준으로 사용하지 않는다. M1은 *IEEE Transactions on Learning Technologies*(대체 *IJAIED* / *JEDM*)를, M2는 *JSS* / *EMSE*(대체 *IST*, "경로 B" 선택 시 학술지 기획 없음)를, M3는 *IEEE TLT* / *IJAIED*를 목표로 한다. **종전의 "목표 저널과 대체 저널이 모두 경비상 장애가 되지 않는다"라는 문장은 불완전하다.** 경비는 확실히 장애가 아니지만 **수록 상태**는 졸업 기준상 실질적 제약이며, 작성자가 대학원과 Scopus 소스 목록에 항목별로 확인한 후에야 확정할 수 있다. 학위논문과 답변용 초록의 언어(한국어 또는 영어) 역시 대학원 확인 후 계획서에 기입하여야 한다. 재현 가능한 artifact는 이미 Zenodo DOI를 취득하여 각 논문의 재현성 선언에서 인용할 수 있다.

## 11 결론

**장 요약**: 본 장은 보고 기간 내의 주요 결론과 전체적 판단을 요약한다.

보고 기간 내에 측정 측과 정적 측의 전체 연구 작업을 완료하여 세 편의 완성 원고를 작성하고, 그중 두 가지 결론을 시스템 코드로 구현 반영하여 14건의 회귀 테스트를 갖추었다. 주요 결론은 다섯 가지로 정리할 수 있다.

1. **난이도 선형 정규화 가중은 측정론적으로 성립하지 않는다.** 불안정성 명제가 성립하며, 유효 가중치는 임의 원천의 단조 재모수화에 따라 드리프트한다; 경험적 CDF → logit의 분위 공척도를 채택한 후 실제 데이터에서의 드리프트가 L1 = 0.5357에서 0.0001로 감소하고 순위 반전이 0으로 귀결된다. **함께 명시하여야 한다**: 명제 중 "분위 공척도 하에서 유효 가중치가 불변"이라는 한쪽은 **해석적 항등식**이며, 본 연구의 기여는 그 항등식이 위반될 때의 차이가 얼마나 큰지를 정량화한 것이지 "명제를 증명한 것"이 아니다. **동시에 명시할 것**: 명제 가운데 "분위 공척도에서 유효 가중치가 불변"이라는 측은 **해석적 항등식**이며, 본 연구의 기여는 그 항등식이 위반될 때의 차이가 얼마나 큰지를 정량화한 것이지 "명제를 증명"한 것이 아니다.
2. **다중 신호 융합의 이득은 "전문가 라벨과의 일치도 이득"이며, 예측력 향상이 아니다.** 판정기준 전환 후 융합은 전부의 표본 크기 구간에서 부로 반전되고 승률은 0.00이다. **동시에 명시할 것**: 홀드아웃 판정량이 성공률일 때 성공률 추정기가 대표본에서 우세한 것은 **설계상 예상 가능하다**(기준선이 곧 판정량의 소표본 추정이다). 따라서 안전한 표현은 "융합의 역할은 소표본에서의 순위 안정화"이며, "일치도 이득은 예측력 이득이 아니다"를 주장하려면 능력 교정 판정기준과 외생 판정기준 두 가지 실험을 추가로 완료하였다(2026-09-23: A1(Junyi, 1,274문항) ρ=0.963/0.892; A2(DBE-KT22 212문항) 0.205/0.220, κ=0.123).
3. **방향이 잘못된 신호는 제거가 아니라 교정되어야 한다.** 상승률을 전체 열 제거에서 부호 교정으로 바꾸고 반분 신뢰도 가중을 더한 후 얻은 추정기는 레코드 수준과 학생 수준 이중 홀드아웃에서 모두 기준선보다 열등하지 않으며, 모든 표본 크기 구간에서 제거식 방안보다 우수하다.
4. **개입 7-튜플에 대한 정적 감사는 구현 완성도상의 중대한 공백을 발견하였다.** **등록 54 / 효과 생산 2 / 성숙도 complete 9·partial 37·placeholder 8**인 시스템에서 77.8%의 메커니즘이 7-튜플로 분류될 수 없으며, 그 원인은 그중 네 필드가 본 프로젝트 코드에 **아직 구현되지 않았다**는 것이다; 이 구현 상태에서 런타임에 검출 가능한 개입 충돌은 1쌍, 예산 경쟁은 0이다. **본 결과는 구현 완성도의 진단으로 규정하며, 반증 조건이 발동한 일반적 "발견"이 아니다.** 본 보고서는 **종전의 "충돌은 보편적이지 않다""대다수 동종 시스템이 충돌을 회피한다""희소 표본"이라는 세 외삽을 철회**한다. 사유는 자료가 "충돌 희소"와 "충돌이 발생할 수 있는 런타임의 부재"를 구분할 수 없고(실제 사용자 로그 = 0), 교차 시스템 증거가 n = 2에 불과하기 때문이다.
5. **난이도 사전확률의 신뢰성이 단일 모델에서 측정되었으나, "LLM의 경계"라는 명제를 뒷받침하기에는 부족하다.** 단일 모델(Qwen3.6-35B-A3B / IQ3_S)이 DBE-KT22에서 전문가 난이도와의 일치도가 ρ = 0.2195(절대 평정)와 0.1808(정렬 + Bradley-Terry)이며, 두 값의 차이는 문항 수준 짝지음 bootstrap에서 **유의하지 않다**(Δ = 0.0385, 95% CI [−0.0652, 0.2193], p = 0.34); 중국어 학과 문항에서는 ρ = −0.038로 유의하지 않다. **종전의 "동일 모델이 프로토콜이 다르기만 해서 네 가지 답을 얻는다"는 문장은 삭제**하였다. 그중 두 값은 실패한 프로토콜 구현에서 나온 것(token 예산에 의한 절단, 절반 이상 파싱 실패)이며 능력의 추정값이 아니다. 제목급 주장을 세우려면 먼저 ≥ 3 모델 계열 × ≥ 3 규모의 주석 행렬을 완성하여야 한다.

**전체 판단**: 본 연구의 핵심 기여는 더 정확한 예측 모델을 제시하는 데 있지 않고, 적응형 학습에서 "난이도"라는, 모든 구성요소가 공유하지만 한 번도 형식화된 적 없는 핵심량을 측정, 목표, 의사결정, 거버넌스 네 가지의 개별 검증 가능한 문제로 분해하고, 각 지점에 증거를 갖춘 결론을 제시하는 데 있다. 직관적 예상과 반대되는 결론, 자신의 이전 설계와 반대되는 결론을 포함하여 그러하다. **동시에 두 가지 경계를 인정하여야 한다.** 첫째, 세 지점의 증거 강도는 동일하지 않다. 거버넌스 체인은 현재 "한 차례의 제한적 내부 정적 감사"만을 지지하고, 의사결정 체인의 LLM 부분은 **하나의 모델**만을 포괄한다. 둘째, 인과 측 식별과 인간 피험자 검증은 **아직 실행되지 않았으며**, 이는 본 연구 다음 단계의 주된 과제이다. 보고서는 미실행 항목에 관하여 어떠한 추측적 표현도 하지 않는다.
