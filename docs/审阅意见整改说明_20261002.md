**意见**：A1 的融合与成功率基线使用了与判据 `b_j` 相同的半样本，`0.963` 是同一半、同一批作答的两个量之间的相关，共享抽样噪声。

**处置（已闭环 —— 代码 + 重跑）**

`results/m1/run_a1a2_fit.py::run_a1()` 改为**融合与成功率基线同在 A 半**，再与 B 半的 `b_j` 比较：

```python
rho_fusion_A  = V.spearman_rho(b, fusion_A)     # 融合(A) vs b_j(B)
rho_success_A = V.spearman_rho(b, sig_success)  # 成功率(A) vs b_j(B)
rho_within_A  = V.spearman_rho(sig_success, fusion_A)  # A 半内两量相关
```

| Spearman(成功率_A, 融合_A)（A 半内） | **0.9404** | — |

## 7. 审阅 §3.2 —— 致命：A2 与第 6 节在同一比较上给出相反结果

**意见**：同一融合在两个实验里一正一负，根因是两个实验各自构造信号，口径不同。

**处置（已闭环 —— 代码 + 重跑）**：新建**唯一信号构造源** `results/code/dbe_signals.py::build(minn=30)`，O4 与 A2 一律调用它；四点口径统一：
① 全交易（不排除 `is_hidden`）；② 反馈取有反馈记录行的均值；③ 时长限定 0 ≤ d < 3600；④ ECDF 取 `(rank − 0.5) / n`。
五个信号**统一"正 = 难"**：`success_inverse = −ecdf_logit(成功率)`、`hint_rate`/`difficulty_fb`/`duration` 取正、`trust_inverse` 取负。

同时修复两处实现缺陷：
- `dbe_signals.py` 曾把成功率取反后又在 M 构造中二次取反，致 `success_inverse` 符号错误（得 −0.2204）；现改为存正成功率，`−ecdf_logit` 得正号。
- `o4_fusion.py` 重构后输出字典引用未定义的 `MINN` 致 `NameError` 不落盘；已补 `MINN = 30`。

**重跑结果（2026-10-02，O4 与 A2 现为同一个数）**

| 量 | 值 |
|---|---:|
| 等权融合 Spearman（A2 / O4 一致） | **0.2918** |
| 仅成功率 | **0.2204** |
| `success_inverse` 单信号 | 0.2204 |
| `trust_inverse` / `duration` / `hint_rate` / `difficulty_fb` | 0.2603 / 0.2434 / −0.1176 / 0.0453 |
| 优化权重（5 折） / 重复 5 折 ×10 | 0.5367 / 0.4862 |

**证据**：`results/code/dbe_signals.py`、`results/code/o4_fusion.py`、`results/code/o4_fusion_results.json`、`results/m1/run_a1a2_fit.py`、`results/m1/m1_criteria_results.json`。
